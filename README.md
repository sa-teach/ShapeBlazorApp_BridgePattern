## Что такое паттерн Bridge

**Bridge (Мост)** — структурный паттерн проектирования, который разделяет абстракцию и реализацию так, чтобы они могли меняться независимо.

Проще говоря:
- **Абстракция** — описывает *что* делать (логика, структура).
- **Реализация** — описывает *как* это делать (конкретные детали).

Они связаны через **композицию**, а не наследование. Абстракция содержит ссылку на реализацию и делегирует ей работу.

### Классическая диаграмма

```
    Abstraction                    Implementation
┌──────────────────┐              ┌──────────────────┐
│  + Operation()   │─────────────►│  + Method()      │
│  - impl          │   делегирует │                  │
└────────┬─────────┘              └────────┬─────────┘
         │                                 │
         │ extends                         │ implements
         ▼                                 ▼
┌──────────────────┐              ┌──────────────────┐
│ RefinedAbstraction│             │ ConcreteImpl     │
└──────────────────┘              └──────────────────┘
```

## Когда он нужен и зачем

### Проблема без Bridge

Если у вас есть несколько типов фигур (круг, квадрат, треугольник) и несколько способов рисования (растр, вектор, OpenGL), то без паттерна Bridge вы получаете **взрыв комбинаций**:

```
CircleRaster, CircleVector, CircleOpenGL,
SquareRaster, SquareVector, SquareOpenGL,
TriangleRaster, TriangleVector, TriangleOpenGL...
```

Каждая новая фигура × каждый новый рендерер = новый класс. Это плохо масштабируется.

### Решение через Bridge

Абстракция (фигура) и реализация (рендерер) живут отдельно. Фигура получает рендерер через конструктор:

```
Circle + RasterRenderer  →  круг в растровом виде
Circle + VectorRenderer  →  круг в векторном виде
Square + VectorRenderer  →  квадрат в векторном виде
```

Добавление новой фигуры или нового рендерера не требует менять уже существующие классы.

### Когда применять Bridge

- Есть несколько «абстракций» и несколько «реализаций», и их комбинации растут.
- Нужно менять реализацию во время выполнения.
- Нужно скрыть детали реализации от клиентского кода.
- Хотите избежать постоянной иерархии наследования.

## Как реализован паттерн в этом проекте

### 1. Интерфейс реализации (IRenderer)

Определяет *как* рисовать примитивы. Фигуры об этом не знают — они только вызывают методы рендерера.

```csharp
public interface IRenderer
{
    string RenderCircle(double cx, double cy, double r);
    string RenderRectangle(double x, double y, double width, double height);
    string RenderLine(double x1, double y1, double x2, double y2);
    string RenderTriangle(double x1, double y1, double x2, double y2, double x3, double y3);
    string Name { get; }
}
```

### 2. Конкретные рендереры

| Класс | Описание |
|-------|----------|
| **RasterRenderer** | Рисует фигуры как набор маленьких квадратов (имитация пикселей) |
| **VectorRenderer** | Рисует гладкие SVG-примитивы (circle, rect, polygon) |

### 3. Абстракция (Shape)

Фигура знает *что* рисовать (геометрию), но не *как*. Рендерер передаётся в конструктор.

```csharp
public abstract class Shape
{
    protected readonly IRenderer Renderer;

    protected Shape(IRenderer renderer)
    {
        Renderer = renderer ?? throw new ArgumentNullException(nameof(renderer));
    }

    public abstract string Draw();
    public abstract string Name { get; }
}
```

### 4. Конкретные фигуры (Refined Abstraction)

Пример — `Circle`:

```csharp
public class Circle : Shape
{
    public double CenterX { get; }
    public double CenterY { get; }
    public double Radius { get; }

    public Circle(IRenderer renderer, double cx, double cy, double radius)
        : base(renderer)
    {
        CenterX = cx;
        CenterY = cy;
        Radius = radius;
    }

    public override string Draw() => Renderer.RenderCircle(CenterX, CenterY, Radius);
    public override string Name => "Круг";
}
```

Круг хранит параметры геометрии и делегирует отрисовку `Renderer.RenderCircle(...)`.

### 5. Использование в Blazor-странице

На странице `/bridge` создаются фигуры с выбранным рендерером:

```csharp
var r = CurrentRenderer;  // RasterRenderer или VectorRenderer
Shapes = new List<Shape>
{
    new Circle(r, 50, 50, 40),
    new Square(r, 10, 10, 80),
    new Triangle(r, 50, 50, 70)
};
```

При смене рендерера в выпадающем списке фигуры пересоздаются с новым рендерером — визуализация меняется без изменения кода фигур.

## Запуск и проверка

### Требования

- .NET 10 SDK (или .NET 8/9 — проект можно переключить в `.csproj`)

### Команды

```bash
# Клонировать репозиторий
git clone <url-репозитория>
cd ShapeBlazorApp_BridgePattern

# Восстановить зависимости
dotnet restore

# Сборка
dotnet build

# Запуск
dotnet run
```

Откройте в браузере адрес из консоли (обычно `https://localhost:5001` или `http://localhost:5000`).

### Что проверить

1. **Главная** — краткое описание паттерна Bridge.
2. **Bridge — Фигуры** (меню) — три фигуры: Круг, Квадрат, Треугольник.
3. Переключение рендерера:
   - **Растровый** — фигуры «пиксельные» (квадратики).
   - **Векторный** — гладкие SVG-фигуры.

## Как расширить проект

### Добавить новый рендерер (например, OpenGLRenderer)

1. Создать класс, реализующий `IRenderer`.
2. Реализовать все методы интерфейса.
3. Добавить экземпляр в список `Renderers` в `Bridge.razor`.

Классы фигур менять не нужно.

### Добавить новую фигуру (например, Pentagon)

1. Создать класс, наследующий `Shape`.
2. В конструкторе принять `IRenderer` и вызвать `base(renderer)`.
3. В `Draw()` вызвать нужные методы рендерера (при необходимости добавить `RenderPolygon` в `IRenderer`).
4. Добавить фигуру в `RebuildShapes()` в `Bridge.razor`.

Классы рендереров менять не нужно.

## Ключевые выводы для студентов

1. **Bridge разделяет «что» и «как»** — абстракция описывает логику, реализация — детали. Связь через композицию.

2. **Композиция важнее наследования** — фигура хранит ссылку на рендерер и делегирует ему работу. Это даёт гибкость.

3. **Расширяемость** — можно добавлять новые фигуры и новые рендереры по отдельности, без изменения уже существующего кода.

4. **Замена реализации на лету** — в этом проекте при смене рендерера в UI создаются новые фигуры с другим рендерером. Та же абстракция, другая реализация.

5. **Отличие от Strategy** — Strategy меняет алгоритм целиком. Bridge разделяет абстракцию и реализацию так, чтобы они могли меняться независимо и жить в разных иерархиях.
